# Changelog

## Unreleased

- Package scaffold for `@localmind/n8n-nodes-localmind` on the n8n node CLI in strict mode, as one package for n8n 2.16 or later.
- Credential "Localmind API" (API URL and user API key). The test lists the key's agents and answers a wrong key or an "-app" host with a message that says what to fix.
- Shared request helper: retries 429 (for Ask and the Chat Model without streaming only one that came before the agent acted), and 5xx and dropped connections for repeatable requests, with Retry-After or exponential backoff; errors read "Localmind: <detail>" with the HTTP status.
- Node "Localmind": Agent → Ask, Get, Get Many; Space → Get Many; searchable agent, space, conversation and document pickers; folder dropdown.
- Agent → Ask: one prompt with optional system message, temperature, maximum tokens and JSON output; images and documents (PDF, Office, text, CSV) as attachments; generated files as binary data.
- Document → Search, Get, Get Many, Get Text, Get Chunks, Reprocess, Update Metadata (merged, Localmind's own fields kept), Delete (through the file manager, so the file and search index go too).
- File → Upload (optionally waiting until indexed, returning the document ID), List, Download, Download by URL, Move or Rename, Delete. Job → Get, optionally waiting until the run ends.
- Hints on Ask and Send Message point to the other operation for the cases it covers.
- README states the minimum Localmind version per feature.
- Conversation → Create, Get, Get Many, Get Messages, Delete, Send Message. Send Message queues the turn, waits through the code-execution queue by polling the conversation state, returns the answer with generated files as binary data, and stops with a message that says what the agent was doing when the timeout (15 minutes by default) runs out. Attachments: images and text files. Option to disable tools by ID. On Localmind up to 1.5.0, whose state endpoint does not accept API keys, Send Message waits by following the run and the message history instead.
- Node "Localmind Chat Model": a Localmind agent as chat model for n8n's AI Agent, with streaming (including token usage) and the PDF, text and CSV files n8n's AI Agent passes on. "[Error: …]" answers become errors, connected n8n tools stop the run with a clear error, and an empty answer is an error. An output parser works without streaming on n8n 2.16 and later (the agent's JSON is handed over as the parser's tool call) and with streaming on newer n8n such as 2.41 (as text). Images and Office files from the chat do not reach the agent.
- An agent that stops at its step limit fails Ask, Send Message and the Chat Model with an error instead of passing on an incomplete answer. Ask and the Chat Model wait at most 10 minutes, as long as Localmind lets one answer run.
- Failed items go to the error output with "Continue (using error output)", with the details in the error text. Job → Get reports a failed run's error as `errorMessage`. Download by URL refuses links with "." or ".." segments, and redirects are followed only to the same address or from http to https. Waits and retry pauses stop when the n8n execution is cancelled. The API key never goes to another host, port or unencrypted address through a redirect.
- Send Message keeps waiting while a turn continues after its sandbox wait, up to its timeout (on Localmind up to 1.5.0 it cannot tell a failed continuation from a running one, so the timeout message says to check the answer before resending), and Get Messages shows such a turn as `in progress`. Ask and conversations accept JPEG, PNG, GIF and WebP images and refuse other image types with a clear message.
- Operations with large answers have n8n's 'Simplify' option (on by default, at most ten fields in camelCase). The reply text is `text` in Ask, Send Message and Get Messages; option groups are named `options`; Document → Search has a 'Limit'; downloads put the file in `binaryPropertyName`, and the prefix of generated files is configurable. Update Metadata starts empty, and a record-only Document → Delete says so (`recordOnly`).
- Hardening: download links are checked on the final path (no ".", "..", empty segments or encoded slashes); generated-file downloads are limited in number and size and are off by default in tool mode; answers are parsed without patterns that slow down on crafted input; MIME types, IDs and folder paths are validated; malformed API data no longer fails whole operations; network errors no longer keep the request with the API key; the credential test does not follow redirects. The customer guide has a section on using the node as an AI tool.
- Stop also ends archive uploads and generated-file downloads instead of moving on to the next file; the Chat Model closes its stream; a retried DELETE that finds the item already gone (404) counts as done; the Chat Model refuses image types Localmind does not take; an expression that returns a plain object is sent as JSON, and a date as its ISO text; short timeouts are named in seconds; a web page answered instead of API data gives a clear error. Errors inside successful items are always `errorMessage`, and files Localmind only stores are `stored` in File → Upload and in simplified document output.
- Unit tests (Vitest), a TypeScript check of code and tests, and CI on GitHub Actions for lint, type check, tests, build, dependency signatures and package contents. Releases are published with npm provenance after a maintainer's approval.
- Ask and the Chat Model fail with a clear error when Localmind (1.6.0 or later) ends an answer because all code sandboxes are busy, instead of passing on Localmind's notice as the answer or failing on it as invalid JSON. The customer guide now says correctly which download links a key's space limit covers.
- Generated files whose names contain spaces, umlauts or brackets download from Ask, Send Message and Get Messages also when Localmind sends their links encoded (from 1.7.0). The node tells the two forms apart by the file's name, so names with a "%" in them and links saved before an upgrade keep working, and a file listed with both forms is downloaded once.
- The README and the customer guide say how the agent's answer language and what it learns about the key's user change with Localmind 1.7.0. Release check 2 has the agent name its file `Release Check Ü (1).xlsx`, so every release run checks the download link's encoding.
- Hardening against a broken or hostile server: errors reach n8n as a short message (a deeply nested error answer could block n8n for minutes), and streamed or binary error answers are read up to 64 KB; Send Message follows at most 50 runs per message, so a server that keeps naming new runs cannot keep it polling without pause; 'Return All' stops after 1,000 pages; a streamed Chat Model answer ends at its timeout even after it started; names and types of downloaded files are cleaned (no folders, control characters or direction marks).
- Releases start by hand from `main` (Actions → Publish → Run workflow) and need a second maintainer's approval. The workflow builds and packs the package in a job without publishing rights, installs the dev tools without their install scripts, publishes exactly that file from a job that installs nothing, and then tags the commit and creates the GitHub release itself.
- The API URL must use https. Plain http works only for this machine (localhost, \*.localhost, 127.0.0.1); for any other host the credential sends no key, its test fails without connecting anywhere, and the nodes stop with "Localmind: the API URL must use https".
- Send Message and Get Messages read generated files from Localmind's documented `generated_files` field (1.7.0 and later) and fall back to the message's display data on older versions. The README states 1.0.0 for generated files instead of 1.2.0.
- Send Message attaches PDF, Office and other files on Localmind 1.7.0: it uploads them for the conversation, waits until Localmind has processed them, and sends the references, so the agent gets their text and the original in its code sandbox. Names keep their umlauts, duplicates within a message are numbered, a name without extension gets one from the file's type, and Localmind's refusals are explained by their code. A text file whose type the space does not take as an upload goes along inline, as before. Images sent as a generic type are recognised by their bytes. Every field is checked before the first upload, and a Localmind up to 1.6.0, which takes no uploads from an API key, is recognised once per execution. Processing has a wait of the timeout's length of its own.
- AI-label files from Localmind 1.7.0 (`<name>.provenance.json`) are passed on marked `provenance: true` and do not count towards 'Max Files to Download' (they have their own count of the same size). The README and the guide name the download limit for file names outside Latin-1 up to 1.6.0.
- Ask and the Chat Model retry a `429` that came before the agent acted: Localmind 1.7.0's rate limit (OpenAI format, `rate_limit_error`), which it answers only before the agent acts. Localmind up to 1.6.0 can answer `429` after a graph agent's first tools ran, and a proxy's text page may hide such an answer; those stay errors.
- Names of downloaded and uploaded files are limited to 200 bytes instead of 200 characters, so that long names in Chinese or with umlauts fit the 255 bytes of file systems and the code sandbox.
- The credential sets n8n's 'Allowed HTTP Request Domains' to None by default, so that n8n's HTTP Request node cannot send the key to another host by mistake; Specific Domains allows the API host.
- File → Download and Download by URL have a 'Max File Size (MB)' option (50 MB by default). All downloads, generated files included, are received as a stream that stops at the limit, so a larger file never fills n8n's memory.
- Download by URL takes only links whose path starts with the download endpoint, not links to other sites that contain it. File-manager paths with "." or ".." segments are refused before anything is sent.
- An API key that Localmind's error text repeats is masked. File names lose invisible format characters (zero-width spaces, soft hyphens, direction marks) but keep the joiners Persian and emoji need.
- AI-label files count as such only next to their file in the list, and are downloaded up to 1 MB each.
- Send Message checks Disabled Tool IDs before uploading attachments, starts no upload once the time is up, and reads the attachments one at a time.
- The release's publish job checks the packed file with nothing installed: its name and SHA-256, its `package.json` against the repository's, and its contents. The first-publish token is `NPM_FIRST_PUBLISH_TOKEN`, refused once the package exists. The tag is created through the API, which refuses an existing one; a failed run can be re-run. npm's record of the package is checked for dependencies and install scripts. The verification command checks the signing workflow and `main`.
- Uploads (File → Upload, attachments, and messages that carry more than 1 MB of images or text themselves) wait up to 60 minutes, which also covers sending the file; other requests up to 5 minutes. A read that runs out of time is tried once more; an upload or a message is not repeated, and its error says Localmind may have carried it out anyway. A download that sends no data for 5 minutes, or breaks off, fails with a "Localmind:" error. A decimal 'Max File Size (MB)' works.
- Download by URL takes links behind a path prefix again, but only in the link's path, not in its query or fragment or after "//"; paths are matched case-sensitively. File → Upload refuses a 'File Name' with a slash, which would pick another folder, and takes the last part of a binary's file name that carries a path (`C:\fakepath\offer.pdf`).
- The Chat Model stops a streamed answer larger than 32 MB.
- The release's privileged jobs take the package name, version and tag only from the repository; the build job hands over just the file name and SHA-256, both checked. The publish job can read the repository while it is private, and checks right before publishing that the tag is free. npm's record of the package is compared with `package.json` for everything that changes an installation. A re-run accepts an existing release only when it is published and holds the same file. Every job has a time limit. CI checks the packed file the way the publish job does.
- The package check also refuses IPv6 addresses, host names of internal networks, and `bin`, `man`, `directories` or `gypfile` in `package.json`; it has tests now.
- The nodes and the credential show the Localmind mark as a vector icon, black in n8n's light theme and white in its dark theme, instead of an embedded picture.
- Send Message checks that every attachment can be read, reading only its first bytes, before the first upload. Download stalls no longer keep received data in memory. Size limits in messages show decimals (1.1 MB).
